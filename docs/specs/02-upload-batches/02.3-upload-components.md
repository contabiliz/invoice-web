# Spec 02.3: Upload Batch — Componentes UI & Acessibilidade

## 1. Overview

Esta seção descreve a hierarquia, anatomia e contratos (props) dos componentes React que formam a tela de upload (PRD-02). 

A arquitetura visual é pautada pelo **Design System Contabiliz DS** (wireframes Stitch), com paleta monocromática contrastante (`#f7f9fb` a `#041627`), tipografia (Manrope para Display, Inter para Content, JetBrains Mono para dados técnicos) e animações utilitárias.

Em conformidade com Next.js App Router, os componentes obedecem à divisão rígida entre `Server Components` (estruturais) e `Client Components` (interativos).

**Uso de i18n nos componentes:**  
Todos os Client Components do upload que exibem texto usam `useTranslations('upload')` do `next-intl`. Nenhuma string de UI é hardcoded. O hook `useBatchUpload` propaga chaves semânticas (ex: `'errors.rate_limited'`); o componente resolve via `t(errorKey)`.

## 3. Architecture Decision Records (ADRs)

### ADR-001: Demarcação SSR vs Client Components

- **Context:** A rota `/upload` está sob `(protected)` — o middleware já verificou autenticação. A tela não precisa de dados do servidor na montagem inicial.
- **Decision:** `UploadPage` é Server Component (shell + metadados da rota). `UploadView` e todos os filhos são Client Components com `"use client"`.
- **Reasons:** Arquivos nativos do browser (`File`) não cruzam o boundary SSR. Todo estado interativo vive no cliente. SSR do shell garante TTFB e LCP rápidos (alvo: LCP < 1.5s, PRD T-PERF-03).
- **Consequences:** Nenhum dado de servidor é necessário na montagem inicial. O layout e metadados são renderizados no servidor; a interação começa no cliente.

### ADR-002: Disclosure Progressivo da Lista de Arquivos

- **Context:** O requisito permite até 500 arquivos. Renderizar 500 itens DOM complexos de uma vez causa TBT alto.
- **Decision:** `FileList` usa `max-height` com scroll para até ~50 itens visíveis. Para batches maiores, exibe apenas arquivos com status `uploading` ou `error` por padrão, com botão "Ver todos" para expandir. Sem biblioteca de windowing nesta versão.
- **Reasons:** Windowing (react-virtualized, tanstack/virtual) adiciona débito técnico significativo para um caso de uso que pode ser adequadamente endereçado com disclosure progressivo. PRD T-PERF-01 exige que adição de 500 arquivos não cause jank — atendido ao não renderizar todos simultaneamente.
- **Consequences:** O usuário pode não ver todos os arquivos de uma vez por padrão em batches grandes. O comportamento de disclosure deve ser testado com 500 arquivos.

## 4. Hierarquia de Componentes

```
app/(protected)/upload/page.tsx (SC)
 └── <UploadView /> (CC) — consome useBatchUpload
     ├── <GlobalProgressBeam />       — visível em presigning, uploading, confirming
     ├── <DropZone />                 — visível em idle (substitui FileList)
     │   └── <FileInput />            — input[type=file] oculto, ativado por DropZone
     ├── <FileList />                 — visível em files_selected, presigning, uploading, confirming
     │   └── <FileListItem /> × N
     │       ├── <FileTypeIcon />     — SC, ícone estático por mime_type
     │       ├── <UploadProgressBar /> — barra individual
     │       └── <FileStatusBadge />  — badge de status
     ├── <BatchSummaryBar />          — visível em files_selected e posteriores
     ├── <UploadActions />            — botão Enviar com estados por fase
     └── <UploadResultSummary />      — visível em success_partial, presign_error, confirm_error
```

## 5. Contratos de Componentes

### 5.1. `<UploadView />` (Client Component)

Componente raiz que consome `useBatchUpload()` e distribui estado entre os filhos via props (lifting state up). Não contém lógica de negócio — delega tudo ao hook.

### 5.2. `<DropZone />`

Exibido apenas na fase `idle`. Captura drag-and-drop e clique para abrir `FileInput`.

```tsx
interface DropZoneProps {
  onFilesSelected: (files: File[]) => void;
  isDisabled?: boolean; // Previne seleções durante presigning/uploading
}
```

- Estados visuais: `idle`, `drag-over`, `error` (arquivo inválido arrastado).
- Acessibilidade: `tabindex="0"`, `role="button"`, `Enter`/`Space` ativa o `FileInput`.
- Ao entrar em `drag-over`: fundo assume `primary/5`, borda assume cor primária (`#041627`).

### 5.3. `<FileInput />`

`<input type="file" multiple />` oculto, ativado programaticamente pelo `DropZone`.

```tsx
interface FileInputProps {
  onFilesSelected: (files: File[]) => void;
  acceptedMimeTypes: string; // ex: ".xml,.pdf,image/*"
}
```

- `aria-label="Selecionar arquivos fiscais para upload"`
- `accept` attribute derivado de `ACCEPTED_MIME_TYPES`

### 5.4. `<FileList />`

Exibido em `files_selected`, `presigning`, `uploading`, `confirming`.

```tsx
interface FileListProps {
  items: FileItemState[];
  onRemove: (internalId: string) => void;
  phase: BatchPhase; // Controla se botão de remoção é visível (apenas em files_selected)
}
```

### 5.5. `<FileListItem />`

Item singular na lista. Layout `flex-row items-center`. Sem bordas (No-Line Rule) — divisão por `padding-spacing-4` e `hover:surface-container-low`.

```tsx
interface FileListItemProps {
  item: FileItemState;
  onRemove: () => void;
  showRemoveButton: boolean; // false após presigning
}
```

### 5.6. `<FileTypeIcon />` (Server Component)

Ícone estático baseado no `mime_type`. Não tem estado.

```tsx
interface FileTypeIconProps {
  mimeType: string;
  size?: number; // default: 20
}
```

### 5.7. `<UploadProgressBar />`

Barra `<progress>` acessível. Visível quando `uploadStatus === 'uploading'`.

```tsx
interface UploadProgressBarProps {
  value: number;          // 0–100
  fileLabel: string;      // usado no aria-label
}
```

- `role="progressbar"` `aria-valuenow={value}` `aria-valuemin="0"` `aria-valuemax="100"` `aria-label={\`Progresso de \${fileLabel}\`}`

### 5.8. `<FileStatusBadge />`

Badge de status individual por arquivo.

```tsx
interface FileStatusBadgeProps {
  status: FileUploadStatus | 'validation_error';
  confirmStatus?: 'confirmed' | 'failed';
}
```

### 5.9. `<BatchSummaryBar />`

Contador e tamanho total. Visível a partir de `files_selected`.

```tsx
interface BatchSummaryBarProps {
  count: number;      // total de arquivos na lista (incluindo com validationError)
  validCount: number; // arquivos sem validationError
  totalBytes: number;
}
```

### 5.10. `<UploadActions />`

Botão "Enviar batch" com estados por fase.

```tsx
interface UploadActionsProps {
  phase: BatchPhase;
  validFileCount: number; // Habilita/desabilita o botão
  onSubmit: () => void;
  onRetryPresign: () => void;
  onRetryConfirm: () => void;
}
```

- `aria-busy="true"` e `aria-disabled="true"` durante `presigning`, `uploading`, `confirming`.
- Texto do botão muda por fase: "Enviar batch" / "Preparando upload…" / "Enviando…" / "Verificando documentos…".

### 5.11. `<GlobalProgressBeam />`

Barra ancorada no topo da tela (`z-index: 60`). Visível em `presigning`, `uploading`, `confirming`.

```tsx
interface GlobalProgressBeamProps {
  totalDocs: number;
  completedDocs: number;
  phase: BatchPhase;
}
```

- `aria-label="Progresso geral do upload"`

### 5.12. `<UploadResultSummary />`

Exibe resumo de resultado ou erro. Visível em `success_partial`, `presign_error`, `confirm_error`.

```tsx
interface UploadResultSummaryProps {
  phase: BatchPhase;
  confirmedCount?: number;
  failedItems?: Array<{ documentId: string; reason: string }>;
  presignError?: string;
  confirmError?: string;
  onRetryPresign?: () => void;
  onRetryConfirm?: () => void;
  batchId?: string; // Para o link "Ver batch" em success_partial
}
```

- Em `success_partial`: aviso amarelo com lista de documentos falhos.
- Em `presign_error` / `confirm_error`: banner `role="alert"` com botão "Tentar novamente".

## 6. Acessibilidade (A11Y)

Conforme PRD §02.9:

1. **DropZone**: `Tab` para foco, `Enter`/`Space` para abrir seletor de arquivos.
2. **FileInput**: `aria-label` descritivo, nunca visualmente exposto.
3. **UploadProgressBar**: `role="progressbar"`, `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax="100"`, `aria-label` com nome do arquivo.
4. **GlobalProgressBeam**: `aria-label="Progresso geral do upload"`.
5. **Mensagens de erro**: `role="alert"` ou `aria-live="assertive"`.
6. **Botão em loading**: `aria-busy="true"` e `aria-disabled="true"`.
7. **Arquivo inválido adicionado**: anunciado via `aria-live="polite"`.
8. **Contraste mínimo**: 4.5:1 em todos os estados de texto.

## 7. Tipografia e Design System

Conforme wireframes Stitch "Contabiliz DS":

| Contexto | Fonte | Exemplo |
|---|---|---|
| Título da página | Manrope, `text-4xl` | "Upload de documentos fiscais" |
| Restrições no DropZone | JetBrains Mono | "50 MB máx · XML, PDF, imagem" |
| Corpo e labels | Inter | Nomes de arquivo, mensagens de erro |
| Dados técnicos (CNPJ, tamanho) | JetBrains Mono | "12.345.678/0001-95 · 4,3 MB" |

**Glassmorphism** na nav sobreposta: `backdrop-blur-xl bg-white/80`.  
**No-Line Rule**: divisórias por espaçamento, não por bordas.
