# Spec 01.3 — Auth: Middleware e Proteção de Rotas

> **PRD:** PRD-01 §01.2 (ADR-002, ADR-003), §01.9
> **Última atualização:** 2026-04-04

---

## Visão geral

O `middleware.ts` atual já protege `/upload`, `/batches` e `/analytics`. Esta spec descreve as mudanças necessárias para:
1. Adicionar `/cadastro` como rota pública
2. Redirecionar usuários autenticados que acessam `/login` ou `/cadastro` direto para `/upload`
3. Preservar URL de destino no redirect para login (para retornar após autenticação)

---

## 1. Estado atual (`src/middleware.ts`)

```ts
// Rotas protegidas — lista explícita com startsWith
const isProtectedRoute =
  request.nextUrl.pathname.startsWith('/upload') ||
  request.nextUrl.pathname.startsWith('/batches') ||
  request.nextUrl.pathname.startsWith('/analytics');

if (!user && isProtectedRoute) {
  const url = request.nextUrl.clone();
  url.pathname = '/login';
  return NextResponse.redirect(url);
}
```

**Problemas:**
- `/cadastro` não existe como rota ainda (novo)
- Não há redirect para usuários autenticados que acessam `/login` — conforme T-FUNC-09
- Não preserva a URL de destino para redirecionar após login

## 2. Middleware atualizado

```ts
// src/middleware.ts
import { createServerClient, type CookieOptions } from '@supabase/ssr';
import { NextResponse, type NextRequest } from 'next/server';

// Rotas que requerem sessão ativa
const PROTECTED_PREFIXES = ['/upload', '/batches', '/analytics'];

// Rotas de auth — usuário autenticado não deve acessar
const AUTH_ROUTES = ['/login', '/cadastro'];

export async function middleware(request: NextRequest) {
  let supabaseResponse = NextResponse.next({ request });

  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return request.cookies.getAll();
        },
        setAll(cookiesToSet: { name: string; value: string; options?: CookieOptions }[]) {
          cookiesToSet.forEach(({ name, value }) =>
            request.cookies.set(name, value),
          );
          supabaseResponse = NextResponse.next({ request });
          cookiesToSet.forEach(({ name, value, options }) =>
            supabaseResponse.cookies.set(name, value, options),
          );
        },
      },
    },
  );

  // Usar getUser() — nunca getSession() no middleware (segurança)
  const {
    data: { user },
  } = await supabase.auth.getUser();

  const pathname = request.nextUrl.pathname;

  // 1. Rota protegida sem sessão → redirect para /login com callbackUrl
  const isProtected = PROTECTED_PREFIXES.some((prefix) =>
    pathname.startsWith(prefix),
  );

  if (!user && isProtected) {
    const loginUrl = request.nextUrl.clone();
    loginUrl.pathname = '/login';
    loginUrl.searchParams.set('callbackUrl', pathname);
    return NextResponse.redirect(loginUrl);
  }

  // 2. Rota de auth com sessão ativa → redirect para /upload
  const isAuthRoute = AUTH_ROUTES.includes(pathname);

  if (user && isAuthRoute) {
    const uploadUrl = request.nextUrl.clone();
    uploadUrl.pathname = '/upload';
    uploadUrl.search = ''; // limpa callbackUrl se existir
    return NextResponse.redirect(uploadUrl);
  }

  return supabaseResponse;
}

export const config = {
  matcher: [
    '/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)',
  ],
};
```

## 3. Uso do `callbackUrl` no LoginForm

Após login bem-sucedido, redirecionar para a URL original se disponível:

```ts
// src/components/auth/LoginForm.tsx
import { useSearchParams } from "next/navigation";

// dentro do componente:
const searchParams = useSearchParams();
const callbackUrl = searchParams.get("callbackUrl") ?? "/upload";

// após signIn bem-sucedido:
router.push(callbackUrl);
router.refresh();
```

**Segurança:** Validar que `callbackUrl` não é uma URL externa (proteção contra open redirect):

```ts
// src/lib/auth/utils.ts
export function getSafeCallbackUrl(raw: string | null): string {
  if (!raw) return "/upload";
  // Aceitar apenas caminhos relativos (sem protocolo, sem host)
  try {
    const url = new URL(raw, "http://localhost");
    if (url.origin !== "http://localhost") return "/upload";
    return url.pathname + url.search;
  } catch {
    return "/upload";
  }
}
```

```ts
// No LoginForm, ao invés de usar callbackUrl diretamente:
import { getSafeCallbackUrl } from "@/lib/auth/utils";

const callbackUrl = getSafeCallbackUrl(searchParams.get("callbackUrl"));
router.push(callbackUrl);
```

## 4. Diagrama de fluxo do middleware

```
Request chega
     │
     ├─ getUser() → user = null
     │    │
     │    ├─ pathname startsWith PROTECTED_PREFIXES?
     │    │    └─ SIM → redirect /login?callbackUrl={pathname}
     │    └─ NÃO → next()
     │
     └─ getUser() → user = User
          │
          ├─ pathname in AUTH_ROUTES (/login, /cadastro)?
          │    └─ SIM → redirect /upload
          └─ NÃO → next()
```

---

## 5. Por que `getUser()` e não `getSession()` no middleware

`getSession()` lê o token dos cookies sem validação criptográfica — um atacante que modificar o cookie pode passar a verificação. `getUser()` faz um round-trip ao Supabase Auth para verificar o token, garantindo que a sessão é legítima.

Custo: ~50ms de latência por request no Edge. Aceitável para rotas protegidas.

---

## 6. Proteção contra open redirect

O `callbackUrl` recebido em query param é potencialmente controlado pelo usuário. `getSafeCallbackUrl` rejeita qualquer valor que contenha um host diferente de `localhost` na construção da URL, impedindo redirects para domínios externos.

Exemplos:
- `/upload` → ✅ aceito
- `/batches/abc-123` → ✅ aceito
- `https://evil.com` → ❌ retorna `/upload`
- `//evil.com/phish` → ❌ retorna `/upload`
