# Spec 01.1 — Auth: Estado de Formulário e Schemas de Validação

> **PRD:** PRD-01 §01.4, §01.5.3, §01.6
> **Última atualização:** 2026-04-04

---

## Visão geral

Esta spec define o estado local dos formulários de Login e Cadastro, os schemas Zod, o mapeamento de erros do Supabase Auth para chaves i18n e o fluxo de submit.

Não há estado global nem TanStack Query — toda lógica cabe nos componentes `LoginForm` e `SignupForm` com `react-hook-form` + Supabase JS SDK.

---

## 1. Schemas Zod

```ts
// src/lib/auth/schemas.ts
import { z } from "zod";

export const loginSchema = z.object({
  email: z.string().email("validation.email_invalid"),
  password: z.string().min(1, "validation.password_required"),
});

export const signupSchema = z
  .object({
    email: z.string().email("validation.email_invalid"),
    password: z.string().min(8, "validation.password_too_short"),
    confirmPassword: z.string().min(1, "validation.confirm_required"),
  })
  .refine((data) => data.password === data.confirmPassword, {
    message: "validation.passwords_mismatch",
    path: ["confirmPassword"],
  });

export type LoginFormValues = z.infer<typeof loginSchema>;
export type SignupFormValues = z.infer<typeof signupSchema>;
```

> Os valores das mensagens são chaves i18n — resolvidas via `useTranslations('auth')` no componente, nunca strings literais em PT-BR no schema.

## 2. Estado dos formulários

### LoginForm

```ts
// Gerenciado por react-hook-form
type LoginFormState = {
  email: string;       // campo controlado
  password: string;    // campo controlado

// Estado local adicional (fora do RHF)
type LoginLocalState = {
  isLoading: boolean;       // true durante signInWithPassword()
  submitError: string | null; // chave i18n de erro pós-submit, null = sem erro

```

type SignupFormState = {

type SignupLocalState = {
  isLoading: boolean;
  submitError: string | null;

## 3. Fluxo de submit — LoginForm

```ts
const onSubmit = async (values: LoginFormValues) => {
  setIsLoading(true);
  setSubmitError(null);

  const supabase = createClient(); // browser client
  const { error } = await supabase.auth.signInWithPassword({
    email: values.email,
    password: values.password,
  });

  if (error) {
    setSubmitError(mapSupabaseAuthError(error));
    setIsLoading(false);
    return;
  }

  // Sucesso: @supabase/ssr já escreveu o cookie via resposta
  router.push("/upload");
  router.refresh(); // força Server Components a lerem o cookie atualizado
};
```

**Por que `router.refresh()` depois de `router.push()`:**
O `push()` navega client-side. O `refresh()` invalida o cache de Server Components para que o `layout.tsx` de `(auth)` re-leia o cookie de sessão e não exiba o estado "sem usuário".

## 4. Fluxo de submit — SignupForm

```ts
const onSubmit = async (values: SignupFormValues) => {
  setIsLoading(true);
  setSubmitError(null);

  const supabase = createClient();
  const { error } = await supabase.auth.signUp({
    email: values.email,
    password: values.password,
    // Sem options.data — perfil criado por trigger no banco
  });

  if (error) {
    setSubmitError(mapSupabaseAuthError(error));
    setIsLoading(false);
    return;
  }

  // Pós-sucesso: redireciona para login com flag para exibir toast
  router.push("/login?registered=true");
};
```

**Não chamar `router.refresh()`** no cadastro — o usuário não está autenticado ainda (apenas criou a conta).

## 5. Limpeza do submitError ao editar campos

O banner de erro de submit deve sumir quando o usuário começa a editar qualquer campo. Implementar via `watch` do react-hook-form:

```ts
const watchedFields = watch(); // observa todos os campos

useEffect(() => {
  if (submitError) setSubmitError(null);
}, [watchedFields.email, watchedFields.password]);
// SignupForm: incluir watchedFields.confirmPassword também
```

## 6. Gestão de foco pós-erro

Após um erro de submit, mover o foco para o banner de erro para que leitores de tela anunciem imediatamente:

```ts
const errorBannerRef = useRef<HTMLDivElement>(null);

useEffect(() => {
  if (submitError && errorBannerRef.current) {
    errorBannerRef.current.focus();
  }
}, [submitError]);
```

O banner deve ter `tabIndex={-1}` para ser focável programaticamente sem aparecer na ordem de tab.

## 7. Toast pós-cadastro em `/login`

Na `LoginPage`, ler o search param `registered` e exibir um toast de confirmação:

```ts
// src/app/login/page.tsx (SC)
import { LoginForm } from "@/components/auth/LoginForm";

type Props = {
  searchParams: Promise<{ registered?: string }>;
};

export default async function LoginPage({ searchParams }: Props) {
  const { registered } = await searchParams;
  return <LoginForm showRegisteredToast={registered === "true"} />;
}
```

```ts
// LoginForm.tsx
useEffect(() => {
  if (props.showRegisteredToast) {
    // exibir toast: "Conta criada com sucesso! Faça login para continuar."
    toast.success(t("toast.account_created"));
  }
}, []);
```

## 8. Diagrama de estados (LoginForm)

```
IDLE
 ├─ [onSubmit + Zod válido] ──────────→ LOADING
 │   • isLoading = true
 │   • submitError = null
 │   • campos desabilitados
 │
LOADING
 ├─ [signIn success] ─────────────────→ [router.push('/upload')]
 └─ [signIn error] ───────────────────→ ERROR
      • isLoading = false
      • submitError = chave i18n
      • campos re-habilitados
      • foco → errorBannerRef
ERROR
 ├─ [usuário edita campo] ────────────→ IDLE
 │   • submitError = null (via useEffect)
 └─ [onSubmit novamente] ─────────────→ LOADING
```
