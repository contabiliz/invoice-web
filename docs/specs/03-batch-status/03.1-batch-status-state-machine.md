# Spec 03.1: Batch Status — Máquina de Estados e Orquestração

> PRD de referência: `docs/prd/batch-status.md §03.1–03.6`

## 1. Overview

Esta especificação define o comportamento do estado interativo e o mecanismo de polling adaptativo para a tela de acompanhamento de batch (PRD-03).

A tela é acessada automaticamente após upload bem-sucedido (redirecionado de `/upload` após `success_full`). O usuário acompanha em tempo real quantos documentos foram concluídos, quantos estão processando e quais falharam.

Responsabilidades deste módulo:
- Manter o estado de fase da tela (`BatchUIPhase`).
- Executar polling adaptativo via `setInterval` com intervalo baseado no estado do batch.
- Parar o polling quando o batch atinge estado terminal.
- Prover dados de status e listas de documentos a componentes filhos.

Responsabilidades excluídas:
- Chamadas de rede puras — pertencem à spec `03.2-batch-status-api-client.md`.
- Renderização visual e JSX — spec `03.3-batch-status-components.md`.

## 3. Architecture Decision Records (ADRs)

### ADR-001: Polling via TanStack Query `refetchInterval` — não `setInterval` manual

- **Context:** O PRD ADR-001 propõe `setInterval` com `clearInterval`, mas o projeto já usa TanStack Query v5 (CLAUDE.md stack).
- **Decision:** Usar `useQuery` com `refetchInterval` configurado dinamicamente via função que recebe os dados mais recentes. Ao detectar status terminal, retornar `false` para interromper o polling.
- **Reasons:**
  - TanStack Query gerencia deduplicação, stale/fresh, error retry e background refetch nativamente — elimina boilerplate de `useEffect` + `setInterval`.
  - `refetchInterval: (query) => getPollingInterval(query.state.data)` é a API projetada para esse caso de uso.
  - Consistência com o padrão já estabelecido no projeto via `useDocumentList`.
- **Consequences:** O hook `useBatchStatus` é um wrapper fino sobre `useQuery`. A lógica de intervalo adaptativo fica em `getPollingInterval` — função pura testável isoladamente.

### ADR-002: `useDocumentList` é independente de `useBatchStatus`

- **Context:** PRD §03.13 proíbe explicitamente refazer fetch da lista de documentos a cada tick de polling do status.
- **Decision:** `useDocumentList` é um hook separado com sua própria query key. Ele NÃO é refetchado quando `useBatchStatus` atualiza — apenas na troca de aba ou mudança de página.
- **Reasons:** A lista de 50 documentos é payload significativo. Refazê-la a cada 2s geraria tráfego desnecessário e causaria re-render da tabela inteira — violando T-PERF-02.
- **Consequences:** `useBatchStatus` atualiza contadores KPI; `useDocumentList` atualiza a tabela apenas na interação do usuário (troca de aba/página).

### ADR-003: Estado de aba e paginação em `useState` local

- **Context:** Considerar URL search params (`?tab=failed&page=2`) para preservar estado em refresh.
- **Decision:** Aba ativa (`DocumentTab`) e página atual (`number`) ficam em `useState` local na `BatchStatusView`. Sem URL search params em v1.
- **Reasons:** A tela é de uso transitório — o usuário raramente precisa compartilhar a URL de uma aba específica. A complexidade de `useSearchParams` + `router.push` não justifica o benefício em v1.
- **Consequences:** Refresh da página resetará aba para "Todos" e página para 1. Aceito para v1.

### ADR-004: `await params` no Server Component (Next.js 15)

- **Context:** Next.js 15 tornou `params` uma Promise. Acessar `params.id` diretamente causa erro de tipo e aviso de runtime.
- **Decision:** `BatchStatusPage` (SC) deve usar `const { id } = await params` antes de passar `batchId` para `BatchStatusView`.
- **Reasons:** Conformidade com Next.js 15 — conforme CLAUDE.md regras críticas.
- **Consequences:** `BatchStatusPage` deve ser `async`. `BatchStatusView` recebe `batchId: string` via prop — não acessa `params` diretamente.

## 4. Tipos e Interfaces

```typescript
// src/hooks/useBatchStatus.ts — tipos exportados

// Fase da UI — mapeamento 1:1 com PRD §03.4.1
export type BatchUIPhase =
  | 'loading'          // Carregamento inicial — skeleton
  | 'active_polling'   // Batch em processamento — polling ativo
  | 'polling_error'    // Erro de rede no polling — toast não-bloqueante + retry
  | 'terminal'         // Status final atingido — polling parado
  | 'error_page';      // 404 ou erro irrecuperável

// Status do batch vindo da API
export type BatchStatus =
  | 'pending_upload'
  | 'processing'
  | 'completed'
  | 'partial_failure'
  | 'failed';

// Status de documento individual
export type DocumentStatus =
  | 'pending_upload'
  | 'upload_confirmed'
  | 'queued'
  | 'processing'
  | 'completed'
  | 'failed';

// Tab ativa na UI — mapeamento para query param ?status
export type DocumentTab = 'all' | 'completed' | 'processing' | 'failed';
```

## 5. Assinaturas dos Hooks

### 5.1. `useBatchStatus`

```typescript
/**
 * useBatchStatus
 *
 * Gerencia polling adaptativo do status do batch.
 * Interrompe automaticamente ao atingir status terminal.
 *
 * PRD referência: §03.5.2, §03.5.3
 */
export function useBatchStatus(batchId: string): {
  phase: BatchUIPhase;
  batch: BatchStatusResponse | null;
  isPolling: boolean;    // true enquanto polling ativo (active_polling)
  errorKey: string | null; // chave i18n quando phase === 'error_page'
}
```

Responsabilidades internas:
1. Chamar `getBatchStatus(batchId)` via `useQuery`.
2. Calcular `refetchInterval` via `getPollingInterval(data)`.
3. Derivar `BatchUIPhase` a partir do estado da query e do `batch.status`.
4. Ao receber 404 → fase `error_page` + `errorKey = 'errors.not_found'`.
5. Ao receber 401 → `router.push('/login')` (sem fase de erro).
6. Ao receber erro de rede → fase `polling_error` (toast no componente).

### 5.2. `useDocumentList`

```typescript
/**
 * useDocumentList
 *
 * Busca lista paginada de documentos por aba ativa.
 * NÃO é refetchado pelo polling de status.
 *
 * PRD referência: §03.3.2, §03.3.3
 */
export function useDocumentList(
  batchId: string,
  options: {
    tab: DocumentTab;
    page: number;
    pageSize: number;
  }
): {
  data: DocumentListResponse | null;
  isLoading: boolean;
  errorKey: string | null;
}
```

Query key: `['document-list', batchId, tab, page, pageSize]` — troca de aba ou página invalida o cache e dispara nova requisição.

## 6. Lógica de Polling Adaptativo

```typescript
// Função pura — testável isoladamente
export function getPollingInterval(
  batch: BatchStatusResponse | null
): number | false {
  if (!batch) return false;                         // ainda carregando
  if (isTerminalStatus(batch.status)) return false; // parar polling
  if (batch.processing > 0) return 2_000;           // 2s — documentos ativos
  if (batch.queued > 0) return 5_000;               // 5s — fila cheia, workers ocupados
  return 3_000;                                     // fallback
}

export function isTerminalStatus(status: BatchStatus): boolean {
  return ['completed', 'partial_failure', 'failed'].includes(status);
}
```

Uso com TanStack Query:

```typescript
const query = useQuery({
  queryKey: ['batch-status', batchId],
  queryFn: () => getBatchStatus(batchId),
  refetchInterval: (query) => getPollingInterval(query.state.data ?? null),
  retry: (failureCount, error) => {
    if (isApiError(error, 404) || isApiError(error, 401)) return false;
    return failureCount < 3;
  },
});
```

## 7. Derivação de `BatchUIPhase`

```typescript
function deriveBatchPhase(query: UseQueryResult<BatchStatusResponse>): BatchUIPhase {
  if (query.isLoading && !query.data) return 'loading';
  if (query.isError) {
    if (isApiError(query.error, 404)) return 'error_page';
    return 'polling_error'; // erro de rede — toast + continua tentando
  }
  if (!query.data) return 'loading';
  if (isTerminalStatus(query.data.status)) return 'terminal';
  return 'active_polling';
}
```

**Regra:** `polling_error` é estado transitório — a query continua tentando. Se recuperar, volta para `active_polling`. Se for 404/401, vai para `error_page` (terminal de UI).

## 8. Gestão de Estado

| Dado | Onde vive | Justificativa |
|---|---|---|
| Status do batch | `useBatchStatus` (TanStack Query) | Server state, atualizado via polling |
| Lista de documentos | `useDocumentList` (TanStack Query) | Server state, depende de filtro e página |
| Aba ativa | `useState` em `BatchStatusView` | UI state, transitório |
| Página atual | `useState` em `BatchStatusView` | UI state, reseta ao trocar aba |
| JWT | Supabase JS SDK | Gerenciado pelo SDK — nunca em state local |

## 9. Transições de Fase

```
loading → active_polling   (primeira resposta bem-sucedida, status não-terminal)
loading → terminal         (primeira resposta, status já terminal)
loading → error_page       (404 na carga inicial)
active_polling → terminal  (polling tick retorna status terminal)
active_polling → polling_error (erro de rede — transitório)
polling_error → active_polling (próximo tick bem-sucedido)
polling_error → error_page (401 irrecuperável)
terminal → —               (estado final da UI)
error_page → —             (estado final da UI)
```

## 10. Security

1. JWT acessado exclusivamente via interceptor Axios — nunca em state local ou logs.
2. `batchId` na URL é UUID — não contém dados de usuário.
3. Nenhum dado de documento (`filename`, `error_reason`) é enviado a analytics fora do escopo definido na spec 03.4.
4. Tenant isolation é responsabilidade da API (RLS + JWT) — o frontend trata 404 como "não encontrado ou sem permissão".
