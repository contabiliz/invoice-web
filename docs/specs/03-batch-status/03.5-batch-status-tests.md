## 2. Testes Funcionais

### T-FUNC-01 — Contadores de KPI atualizam sem reload da página

**Onde:** `useBatchStatus` + `KpiCards`  
**Como testar:**

```typescript
// hooks/useBatchStatus.test.ts
it('T-FUNC-01: KPI counters atualizam no próximo tick de polling', async () => {
  vi.useFakeTimers();
  mockGetBatchStatus
    .mockResolvedValueOnce(mockBatchProcessing)  // primeiro fetch
    .mockResolvedValueOnce({                      // segundo fetch (após 2s)
      ...mockBatchProcessing,
      completed: 5,
      processing: 2,
    });

  const { result } = renderHook(() => useBatchStatus('batch-uuid-001'), {
    wrapper: QueryClientWrapper,
  });

  await waitFor(() => expect(result.current.batch?.completed).toBe(2));

  act(() => vi.advanceTimersByTime(2_000));

  await waitFor(() => expect(result.current.batch?.completed).toBe(5));
  vi.useRealTimers();
});
```

### T-FUNC-02 — Polling para quando batch atinge estado terminal

**Onde:** `useBatchStatus`  
**Como testar:**

```typescript
it('T-FUNC-02: polling para após status terminal', async () => {
  vi.useFakeTimers();
  mockGetBatchStatus
    .mockResolvedValueOnce(mockBatchProcessing)
    .mockResolvedValueOnce(mockBatchCompleted);

  const { result } = renderHook(() => useBatchStatus('batch-uuid-001'), {
    wrapper: QueryClientWrapper,
  });

  await waitFor(() => expect(result.current.phase).toBe('active_polling'));
  act(() => vi.advanceTimersByTime(2_000));
  await waitFor(() => expect(result.current.phase).toBe('terminal'));

  const callCountAfterTerminal = mockGetBatchStatus.mock.calls.length;
  act(() => vi.advanceTimersByTime(10_000));
  // polling parou — nenhuma chamada adicional
  expect(mockGetBatchStatus.mock.calls.length).toBe(callCountAfterTerminal);
  vi.useRealTimers();
});
```

### T-FUNC-05 — Troca de aba não reinicia polling — apenas refetch da lista

**Onde:** `useBatchStatus` + `useDocumentList`  
**Como testar:**

```typescript
it('T-FUNC-05: troca de aba não causa refetch de useBatchStatus', async () => {
  vi.useFakeTimers();
  mockGetBatchStatus.mockResolvedValue(mockBatchProcessing);
  mockGetDocumentList.mockResolvedValue(mockDocumentList);

  render(<BatchStatusView batchId="batch-uuid-001" />, {
    wrapper: QueryClientWrapper,
  });

  await waitFor(() => screen.getByRole('tab', { name: /todos/i }));
  const statusCallsBefore = mockGetBatchStatus.mock.calls.length;

  await userEvent.click(screen.getByRole('tab', { name: /concluídos/i }));

  // useBatchStatus não foi chamado adicionalmente por causa da troca de aba

  // useDocumentList foi chamado com nova aba
  expect(mockGetDocumentList).toHaveBeenLastCalledWith(
    'batch-uuid-001',
    expect.objectContaining({ tab: 'completed' }),
  );
  vi.useRealTimers();
});
```

### T-SEC-02 — JWT expirado durante polling → refresh via SDK → polling continua

**Onde:** `apiClient` interceptor + `useBatchStatus`  
**Como testar:**

```typescript
it('T-SEC-02: 401 transitório não para polling — SDK faz refresh e polling continua', async () => {
  vi.useFakeTimers();

  // Primeiro tick: 401 (JWT expirado)
  // Segundo tick após refresh: sucesso
  mockGetBatchStatus
    .mockRejectedValueOnce(new BatchApiError('Unauthorized', 401))
    .mockResolvedValueOnce(mockBatchProcessing);

  // Mock do SDK retornando novo token no refresh
  vi.mocked(supabase.auth.getSession).mockResolvedValue({
    data: { session: { access_token: 'novo-jwt' } },
    error: null,
  } as unknown as Awaited<ReturnType<typeof supabase.auth.getSession>>);

  const { result } = renderHook(() => useBatchStatus('batch-uuid-001'), {
    wrapper: QueryClientWrapper,
  });

  // Após retry automático com novo JWT, polling retoma
  act(() => vi.advanceTimersByTime(2_000));
  await waitFor(() => expect(result.current.phase).toBe('active_polling'));
  expect(result.current.batch).toEqual(mockBatchProcessing);
  vi.useRealTimers();
});
```

### T-PERF-02 — Tick de polling não causa re-render do DocumentTable

**Onde:** `useBatchStatus` vs `DocumentTable`  
**Como testar:**

```typescript
it('T-PERF-02: atualização de status não re-renderiza DocumentTable', async () => {
  vi.useFakeTimers();
  mockGetBatchStatus
    .mockResolvedValueOnce(mockBatchProcessing)
    .mockResolvedValueOnce({ ...mockBatchProcessing, completed: 5 });
  mockGetDocumentList.mockResolvedValue(mockDocumentList);

  const tableRenderSpy = vi.fn();
  // DocumentTable instrumentado com onRender spy via jest-mock-component ou React.memo tracking

  render(
    <BatchStatusView batchId="batch-uuid-001" onDocumentTableRender={tableRenderSpy} />,
    { wrapper: QueryClientWrapper },
  );

  await waitFor(() => expect(tableRenderSpy).toHaveBeenCalledTimes(1)); // render inicial

  act(() => vi.advanceTimersByTime(2_000)); // tick de polling
  await waitFor(() =>
    screen.getByText('5') // KPI atualizado
  );

  // DocumentTable não re-renderizou
  expect(tableRenderSpy).toHaveBeenCalledTimes(1);
  vi.useRealTimers();
});
```

**Implementação:** `DocumentTable` deve ser envolvido em `React.memo`. O `BatchStatusView` não deve passar props derivadas do batch para o `DocumentTable` — apenas para `KpiCards` e `BatchProgressBar`.
