# Spec 03.3: Batch Status — Componentes UI & Acessibilidade

> PRD de referência: `docs/prd/batch-status.md §03.5`

## 1. Overview

Esta seção descreve a hierarquia, anatomia e contratos (props) dos componentes React que formam a tela de Batch Status (PRD-03).

A arquitetura visual segue o **Contabiliz Design System** (Geist Sans/Mono, paleta semântica de status, alta densidade em tabela, disclosure progressivo por tabs). O design de referência é a tela Stitch "Upload — In Progress (Contabiliz DS)" (project `5660826328406993994`).

Em conformidade com Next.js 15 App Router, os componentes obedecem à divisão entre `Server Components` (estruturais/estáticos) e `Client Components` (interativos/com estado).

## 3. Architecture Decision Records (ADRs)

### ADR-001: SC/CC split — `BatchStatusPage` é shell, `BatchStatusView` é orquestrador

- **Context:** A rota `/batches/[id]` está sob `(auth)` — middleware já verificou autenticação. O `batchId` vem de `params` que é Promise no Next.js 15.
- **Decision:** `BatchStatusPage` (SC) faz `await params`, passa `batchId: string` para `BatchStatusView` (CC). Todo estado interativo vive no CC.
- **Reasons:** SC não pode usar hooks. O polling via TanStack Query é client-side. O SC serve como shell com metadados e boundary SSR.
- **Consequences:** `BatchStatusView` e todos os seus filhos são Client Components. Nenhum dado real é SSR — o skeleton é a experiência inicial.

### ADR-002: Tabs com `shadcn/ui Tabs`

- **Context:** PRD ADR-002 exige tabs com contadores visíveis (ex: "Falhou (4)") e troca que filtra a API.
- **Decision:** Usar o componente `Tabs` do `shadcn/ui` (Radix UI primitives). Cada `TabsTrigger` exibe label + badge numérico do contador correspondente do `batch`.
- **Reasons:** Shadcn/ui é o padrão de componentes do projeto (CLAUDE.md). Radix UI garante acessibilidade de tabs (role="tablist", aria-selected, keyboard navigation) sem implementação manual.
- **Consequences:** Troca de aba chama `setActiveTab` no `BatchStatusView`, que propaga para `useDocumentList` via prop. O `DocumentTable` recebe nova lista e reseta para página 1.

### ADR-003: `DocumentRow` com destaque de linha inteira para erros

- **Context:** PRD ADR-004 exige que documentos `status='failed'` tenham toda a linha com `background: var(--color-status-error-bg)`.
- **Decision:** `DocumentRow` recebe `isError: boolean`. Quando `true`, aplica `bg-[var(--color-status-error-bg)]` na `<tr>`.
- **Reasons:** Destaque de linha inteira é mais eficiente para scan visual em tabelas densas do que apenas um badge na coluna de status — padrão Docsumo.
- **Consequences:** A coluna de status ainda exibe `StatusBadge` com variante `error` — o destaque de linha é adicional.

### ADR-004: `ErrorTooltip` acessível via teclado

- **Context:** PRD §03.9 exige que o tooltip de razão técnica seja acessível via teclado (foco + Enter).
- **Decision:** Usar `Tooltip` do `shadcn/ui` com `<TooltipTrigger asChild>` envolvendo um `<button>` invisível na célula de razão.
- **Reasons:** Tooltips puramente de hover não são acessíveis. Radix Tooltip ativa em foco e hover por padrão — satisfaz o requisito sem implementação manual.
- **Consequences:** A célula "Razão" exibe a mensagem PT-BR mapeada como texto truncado. O tooltip revela a `error_reason` técnica completa no hover/foco.

### ADR-005: `PollingIndicator` com `aria-hidden` quando inativo

- **Context:** PRD §03.9 exige `aria-live="polite"` no indicador de atualização.
- **Decision:** `PollingIndicator` renderiza sempre no DOM, mas usa `aria-hidden={!isPolling}` e opacidade CSS para ocultar quando `phase !== 'active_polling'`.
- **Reasons:** Alternar `aria-hidden` é mais acessível do que desmontar/montar o elemento — evita anunciar desnecessariamente para leitores de tela quando o texto aparece subitamente.
- **Consequences:** O componente é renderizado sem conteúdo visual quando `isPolling=false`.

## 4. Hierarquia de Componentes

```
app/(auth)/batches/[id]/page.tsx (SC — async, await params)
 └── <BatchStatusView batchId={string} /> (CC)
     ├── <BatchHeader />              — status dot animado, id[:8], tempo relativo
     ├── <KpiCards />                 — grid 2×2
     │   └── <KpiCard /> × 4         — Total / Concluídos / Processando / Falhou
     ├── <BatchProgressBar />         — progresso global filled = completed/total
     ├── <PollingIndicator />         — "Atualizando…" com spinner, aria-live
     ├── <BatchResultBanner />        — visível apenas em phase === 'terminal'
     ├── <DocumentTabs />             — Shadcn Tabs com contadores no trigger
     │   └── <DocumentTable />        — tabela paginada por aba
     │       └── <DocumentRow /> × N
     │           ├── <DocTypeIcon />  — SC, ícone Lucide por doc_type
     │           ├── <StatusBadge />  — badge semântico por status
     │           └── <ErrorTooltip /> — tooltip com razão técnica completa
     └── <TablePagination />          — prev/next, "Página X de Y"
```

## 5. Contratos de Props

### `BatchStatusView`
```typescript
interface BatchStatusViewProps {
  batchId: string;
}
```
Consome `useBatchStatus(batchId)` e `useDocumentList(batchId, { tab, page, pageSize: 50 })`.
Gerencia `activeTab: DocumentTab` e `currentPage: number` via `useState`.

---

### `BatchHeader`
```typescript
interface BatchHeaderProps {
  batchId: string;          // exibir apenas primeiros 8 caracteres
  status: BatchStatus;
  createdAt: string;        // ISO8601 — exibir como "há X minutos"
  isLoading: boolean;       // skeleton state
}
```
- Status dot: `animate-pulse` em `active_polling`, estático em `terminal`.
- Tempo relativo: usar `Intl.RelativeTimeFormat` — sem biblioteca externa.

---

### `KpiCards`
```typescript
interface KpiCardsProps {
  total: number;
  completed: number;
  processing: number;
  failed: number;
  isLoading: boolean;  // exibe 4 skeleton cards
}
```

---

### `KpiCard`
```typescript
interface KpiCardProps {
  labelKey: string;          // chave i18n: 'kpi.total' | 'kpi.completed' | ...
  value: number;
  variant: 'neutral' | 'success' | 'warning' | 'error';
  isLoading: boolean;
}
```
- Valor numérico: **Geist Mono** + `tabular-nums` (CLAUDE.md regras críticas).
- `aria-live="polite"` no elemento de valor — anuncia atualizações a leitores de tela (PRD §03.9).

---

### `BatchProgressBar`
```typescript
interface BatchProgressBarProps {
  completed: number;
  total: number;
  isLoading: boolean;
}
```
- `<progress value={completed} max={total} />` com `aria-valuenow={completed}` e `aria-valuemax={total}`.
- Barra com `background: var(--color-accent)` — `--color-accent` (#0070F3).

---

### `PollingIndicator`
```typescript
interface PollingIndicatorProps {
  isPolling: boolean;
}
```
- `aria-live="polite"` + `aria-atomic="true"` (PRD §03.9).
- Posicionado no canto superior direito do `BatchStatusView` — `absolute top-4 right-4`.
- Spinner Lucide `Loader2` com `animate-spin`.

---

### `BatchResultBanner`
```typescript
interface BatchResultBannerProps {
  status: 'completed' | 'partial_failure' | 'failed';
  completed: number;
  failed: number;
  onNewUpload: () => void;   // navegar para /upload
}
```
- `role="status"` em `completed` e `partial_failure`.
- `role="alert"` em `failed` (PRD §03.9).
- Cores por variante:
  - `completed` → `var(--color-status-success-bg)` + `var(--color-status-success)`
  - `partial_failure` → `var(--color-status-warning-bg)` + `var(--color-status-warning)`
  - `failed` → `var(--color-status-error-bg)` + `var(--color-status-error)`

### `DocumentTabs`

interface DocumentTabsProps {

- Badge vermelho no trigger "Falhou" quando `counts.failed > 0`.

- Célula exibe `mappedReason` truncado (max 40 chars).
- Tooltip (`shadcn/ui Tooltip`) exibe `technicalReason` completo.
- Ativado por hover E foco (PRD §03.9).

## 8. Acessibilidade

| Requisito | Implementação |
|---|---|
| KPI counters anunciam atualizações | `aria-live="polite"` no `<span>` do valor |
| Indicador "Atualizando…" | `aria-live="polite"` + `aria-atomic="true"` |
| Tabela semântica | `role="table"`, `<thead>`, `<th scope="col">` |
| Tooltip acessível via teclado | `<button>` com `onFocus` via Radix `Tooltip` |
| Banner de resultado | `role="status"` (sucesso) ou `role="alert"` (falha) |
| Tabs | Radix UI — `role="tablist"`, `role="tab"`, `aria-selected`, `arrow key` navigation |
| StatusDot em processamento | Não usar cor isolada — sempre acompanhado de label textual |
