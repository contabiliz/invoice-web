# Spec 03.2: Batch Status — Camada de Cliente de API

> PRD de referência: `docs/prd/batch-status.md §03.3`

## 1. Overview

Esta especificação define a camada de cliente HTTP para as duas requisições consumidas pela tela de Batch Status:

1. `GET /api/v1/batches/{id}` — status do batch com contadores agregados.
2. `GET /api/v1/batches/{id}/documents` — lista paginada de documentos com filtro opcional por status.

Este módulo NÃO gerencia estado de UI nem lógica de polling. Sua responsabilidade começa e termina na rede: montar a requisição, injetar JWT, interpretar a resposta e lançar erros tipados.

## 3. Architecture Decision Records (ADRs)

### ADR-001: Reutilizar instância `apiClient` existente

- **Context:** O módulo `batch-client.ts` (spec 02.2) já criou uma instância Axios com interceptor JWT que chama `supabase.auth.getSession()` em cada requisição.
- **Decision:** `batch-status-client.ts` importa e reutiliza a mesma instância `apiClient` — não cria nova instância Axios.
- **Reasons:** A instância existente já injeta JWT fresco, configura `baseURL` a partir da env var `NEXT_PUBLIC_API_URL`, e padroniza headers. Duplicar seria incoerência arquitetural.
- **Consequences:** `batch-status-client.ts` tem zero configuração de transporte — apenas funções que chamam `apiClient.get(...)`.

### ADR-002: Mapeamento de tab → query param `status`

- **Context:** A UI usa `DocumentTab` ('all' | 'completed' | 'processing' | 'failed'). A API aceita `?status=failed` (opcional — omitir para "todos").
- **Decision:** A função `getDocumentList` recebe `tab: DocumentTab` e mapeia internamente para o query param correto. Tab `'all'` → omite o param `status`.
- **Reasons:** Isolar o mapeamento no cliente evita que os hooks ou componentes precisem conhecer os valores brutos da API. Se a API mudar o enum de status, a alteração é feita em um lugar.
- **Consequences:** O caller (hook `useDocumentList`) passa `tab` diretamente — não precisa construir query string.

### ADR-003: Lançar erros tipados, não retornar `null`

- **Context:** Os hooks precisam distinguir 404, 401 e erro de rede para derivar `BatchUIPhase`.
- **Decision:** O cliente lança `BatchApiError` com `status: number | 'network'`. Os hooks capturam e classificam.
- **Reasons:** `null` como retorno de erro força o caller a testar `if (data === null)` sem saber o motivo. Erros tipados permitem `if (error instanceof BatchApiError && error.status === 404)`.
- **Consequences:** Todas as chamadas ao cliente devem ser em `try/catch`. Os hooks são responsáveis por classificar o erro e derivar a fase de UI correta.

### 4.1. Adicionar em `src/lib/api/types.ts`

```typescript
// ------------------------------------
// GET /api/v1/batches/{id}
// ------------------------------------

export type BatchStatus =
  | 'pending_upload'
  | 'processing'
  | 'completed'
  | 'partial_failure'
  | 'failed';

export interface BatchStatusResponse {
  batch_id: string;
  status: BatchStatus;
  total: number;
  queued: number;
  processing: number;
  completed: number;
  failed: number;
  created_at: string;        // ISO8601
  completed_at: string | null;
}

// ------------------------------------
// GET /api/v1/batches/{id}/documents
// ------------------------------------

export type DocumentStatus =
  | 'pending_upload'
  | 'upload_confirmed'
  | 'queued'
  | 'processing'
  | 'completed'
  | 'failed';

export type DocumentDocType = 'xml' | 'pdf' | 'img';

export interface DocumentItem {
  document_id: string;
  filename: string;
  doc_type: DocumentDocType;
  status: DocumentStatus;
  error_reason: string | null;
  created_at: string;        // ISO8601
  updated_at: string;        // ISO8601
}

export interface DocumentListResponse {
  total: number;
  page: number;
  items: DocumentItem[];
}

// ------------------------------------
// Erro tipado do cliente
// ------------------------------------

export class BatchApiError extends Error {
  constructor(
    message: string,
    public readonly status: number | 'network',
  ) {
    super(message);
    this.name = 'BatchApiError';
  }
}
```

## 5. Implementação do Cliente

```typescript
// src/lib/api/batch-status-client.ts

import { apiClient } from './batch-client'; // instância existente com interceptor JWT
import type {
  BatchStatusResponse,
  DocumentListResponse,
  DocumentStatus,
} from './types';
import { BatchApiError } from './types';
import type { DocumentTab } from '@/hooks/useBatchStatus';

// Mapeamento de aba de UI para query param de status
const TAB_TO_STATUS: Partial<Record<DocumentTab, DocumentStatus>> = {
  completed: 'completed',
  processing: 'processing',
  failed: 'failed',
  // 'all' → omitir param
};

/**
 * GET /api/v1/batches/{id}
 *
 * Retorna status atual e contadores do batch.
 * Lança BatchApiError em 404, 401 ou erro de rede.
 */
export async function getBatchStatus(
  batchId: string,
): Promise<BatchStatusResponse> {
  try {
    const { data } = await apiClient.get<BatchStatusResponse>(
      `/batches/${batchId}`,
    );
    return data;
  } catch (err) {
    throw mapAxiosError(err);
  }
}

/**
 * GET /api/v1/batches/{id}/documents
 *
 * Retorna lista paginada de documentos.
 * Tab 'all' omite o filtro de status.
 */
export async function getDocumentList(
  batchId: string,
  params: {
    tab: DocumentTab;
    page: number;
    pageSize: number;
  },
): Promise<DocumentListResponse> {
  const queryParams: Record<string, unknown> = {
    page: params.page,
    page_size: params.pageSize,
  };

  const statusFilter = TAB_TO_STATUS[params.tab];
  if (statusFilter) {
    queryParams.status = statusFilter;
  }

  try {
    const { data } = await apiClient.get<DocumentListResponse>(
      `/batches/${batchId}/documents`,
      { params: queryParams },
    );
    return data;
  } catch (err) {
    throw mapAxiosError(err);
  }
}

// ------------------------------------
// Utilitário interno
// ------------------------------------

function mapAxiosError(err: unknown): BatchApiError {
  if (isAxiosError(err)) {
    const status = err.response?.status;
    if (status) return new BatchApiError(err.message, status);
  }
  return new BatchApiError('Network error', 'network');
}

function isAxiosError(err: unknown): err is { response?: { status: number }; message: string } {
  return typeof err === 'object' && err !== null && 'isAxiosError' in err;
}
```

## 6. Taxonomia de Erros HTTP

| Status | Causa | Ação no hook |
|---|---|---|
| 401 | JWT expirado e refresh falhou | `router.push('/login')` — sem fase de erro |
| 404 | Batch não existe ou pertence a outro tenant | `phase = 'error_page'`, `errorKey = 'errors.not_found'` |
| 429 | Rate limit | `phase = 'polling_error'` — TanStack Query retrya com backoff |
| 5xx | Erro do servidor | `phase = 'polling_error'` — retry até 3 tentativas |
| `'network'` | Sem conexão | `phase = 'polling_error'` — toast não-bloqueante |

---

## 7. Security

1. JWT é injetado pelo interceptor da instância `apiClient` via `supabase.auth.getSession()` — nunca hardcoded ou lido de localStorage.
2. `batchId` é validado como UUID pelo backend (RLS garante tenant isolation) — o frontend trata 404 como "não encontrado ou sem permissão" sem distinguir os dois casos.
3. Nenhum campo de `DocumentItem` (`filename`, `error_reason`) é enviado a serviços de analytics — apenas `document_id` (UUID) e tipos agregados quando necessário.
4. O cliente nunca loga o conteúdo da resposta — apenas o status code em erros.
