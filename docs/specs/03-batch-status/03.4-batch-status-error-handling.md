# Spec 03.4: Batch Status — Error Handling & Observabilidade

> PRD de referência: `docs/prd/batch-status.md §03.7–03.10`

## 1. Overview

Esta seção define como a tela de Batch Status lida com falhas sistêmicas e de documentos individuais, incluindo: taxonomia visual de erros, mensagens mapeadas em PT-BR, comportamento offline, e diretrizes de observabilidade sem PII.

Dois contextos de erro distintos:
1. **Erros de API/rede** — afetam a tela inteira (poll falhou, batch não encontrado).
2. **Erros de documento** — `error_reason` em `DocumentItem` — afetam linhas individuais da tabela.

---

## 2. Architecture Decision Records (ADRs)

### ADR-001: Mensagens de erro via chaves i18n — nunca strings hardcoded

- **Context:** Consistência com o padrão estabelecido em `02.4-upload-error-handling.md` ADR-001.
- **Decision:** Os hooks propagam **chaves semânticas** (ex: `'errors.not_found'`). Os componentes resolvem via `useTranslations('batch-status')`. Nenhuma string de erro é hardcoded em JSX.
- **Reasons:** Uniformidade de i18n em todo o projeto. Revisão de copy sem tocar em lógica.
- **Consequences:** `useBatchStatus` retorna `errorKey: string | null`. O componente que renderiza o erro chama `t(errorKey)`.

### ADR-002: `error_reason` raw exibida apenas no tooltip — nunca na linha visível

- **Context:** PRD §03.13 proíbe exibir `error_reason` raw na coluna "Razão".
- **Decision:** A célula "Razão" exibe sempre a string PT-BR mapeada por `mapDocumentError(reason)`. O tooltip (hover/foco via `ErrorTooltip`) revela o `error_reason` técnico completo.
- **Reasons:** `error_reason` valores como `'object_not_found'` ou `'classifier_timeout'` são incompreensíveis para analistas fiscais. A mensagem mapeada comunica a causa em linguagem acessível.
- **Consequences:** `mapDocumentError` deve cobrir todos os `error_reason` possíveis retornados pela API. Valores desconhecidos → fallback genérico.

### ADR-003: Polling error é estado não-bloqueante — dados anteriores permanecem visíveis

- **Context:** PRD §03.4.2 define `polling_error_banner` como toast não-bloqueante — a última versão dos dados permanece visível.
- **Decision:** Ao receber erro de rede no polling, TanStack Query mantém `data` do último fetch bem-sucedido. O hook deriva `phase = 'polling_error'`. O componente renderiza um toast (não uma página de erro).
- **Reasons:** Erros de rede transitórios são comuns em ambientes corporativos com VPN. Bloquear a tela inteira por um tick de polling falho é experiência ruim.
- **Consequences:** O toast desaparece automaticamente quando o próximo tick de polling for bem-sucedido (`phase` volta para `active_polling`).

## 3. Taxonomia de Erros

### 3.1. Erros de API (nível de tela)

| Cenário | Status HTTP | `BatchUIPhase` | Componente | Ação do usuário |
|---|---|---|---|---|
| Batch não existe | 404 | `error_page` | Página de erro full | Botão "Voltar para upload" → `/upload` |
| JWT expirado (irrecuperável) | 401 | — | redirect | `router.push('/login')` |
| Erro de rede (transitório) | `'network'` | `polling_error` | Toast | Aguardar reconexão automática |
| Servidor indisponível | 5xx | `polling_error` | Toast | Retry automático (até 3x TanStack Query) |
| Rate limit | 429 | `polling_error` | Toast | Retry com backoff exponencial |

### 3.2. Erros de documento (nível de linha)

| `error_reason` (API) | Mensagem PT-BR (`mapDocumentError`) |
|---|---|
| `object_not_found` | "Arquivo não encontrado no storage" |
| `classifier_timeout` | "Tempo de processamento excedido" |
| `invalid_xml` | "XML inválido ou corrompido" |
| `unsupported_format` | "Formato de arquivo não suportado" |
| `ocr_failed` | "Falha no reconhecimento de texto (OCR)" |
| `duplicate_key` | "Documento já processado anteriormente" |
| `schema_validation_failed` | "Documento fora do padrão fiscal esperado" |
| `_unknown_` (fallback) | "Falha no processamento — contate o suporte" |

## 4. Implementação de `mapDocumentError`

Adicionar em `src/lib/api/errors.ts`:

```typescript
// src/lib/api/errors.ts

const DOCUMENT_ERROR_MAP: Record<string, string> = {
  object_not_found:          'errors.doc.object_not_found',
  classifier_timeout:        'errors.doc.classifier_timeout',
  invalid_xml:               'errors.doc.invalid_xml',
  unsupported_format:        'errors.doc.unsupported_format',
  ocr_failed:                'errors.doc.ocr_failed',
  duplicate_key:             'errors.doc.duplicate_key',
  schema_validation_failed:  'errors.doc.schema_validation_failed',
};

/**
 * Mapeia error_reason da API para chave i18n PT-BR.
 * Valores desconhecidos retornam chave de fallback genérico.
 */
export function mapDocumentError(reason: string | null): string {
  if (!reason) return 'errors.doc.unknown';
  return DOCUMENT_ERROR_MAP[reason] ?? 'errors.doc.unknown';
}
```

O componente `ErrorTooltip` recebe:
- `mappedReason = t(mapDocumentError(item.error_reason))` — exibido na célula
- `technicalReason = item.error_reason ?? ''` — exibido no tooltip

## 6. Padrões Visuais de Erro

### 6.1. `error_page` (404)

Renderiza em lugar do `BatchStatusView` completo:

```
┌─────────────────────────────────────────┐
│  [ícone AlertCircle — vermelho]         │
│  "Batch não encontrado ou sem permissão."│
│  [botão] "Voltar para upload"           │
└─────────────────────────────────────────┘
```

- Background: `var(--color-bg-surface)`, centralizado verticalmente.
- Botão: `variant="outline"` (shadcn/ui Button), navega para `/upload`.

### 6.2. `polling_error` (toast não-bloqueante)

- Componente: `toast` do `shadcn/ui` (Sonner ou shadcn toast).
- Posição: canto inferior direito — não bloqueia a tabela.
- Ícone: `WifiOff` (Lucide).
- Desaparece automaticamente ao recuperar conexão (`phase` volta para `active_polling`).

### 6.3. Linha de documento com erro

- Fundo: `var(--color-status-error-bg)` em toda a `<tr>`.
- Coluna "Razão": texto mapeado PT-BR + botão de tooltip `[?]` para razão técnica.
- Badge: variante `error` — `var(--color-status-error)` + `var(--color-status-error-bg)`.

## 7. Eventos de Observabilidade

```typescript
// src/lib/observability/batch-status-events.ts

export type BatchStatusObservabilityEvent =
  | {
      event: 'batch_viewed';
      batch_id: string;    // UUID apenas — não contém dados de usuário
      doc_count: number;
    }
  | {
      event: 'batch_completed_seen';
      status: 'completed' | 'partial_failure' | 'failed';
      completed_count: number;
      failed_count: number;
      duration_ms: number; // created_at → completed_at
    }
  | {
      event: 'batch_error_tab_opened';
      failed_count: number;
    };
```

### 7.1. Restrições de privacidade (LGPD)

| Dado | Pode enviar a analytics? |
|---|---|
| `batch_id` (UUID) | ✅ Sim |
| `doc_count`, `completed_count`, `failed_count` | ✅ Sim |
| `duration_ms` | ✅ Sim |
| `filename` de qualquer documento | ❌ Nunca — pode conter CNPJ |
| `error_reason` raw | ❌ Nunca — pode revelar estrutura interna |
| JWT | ❌ Nunca |
| `document_id` (UUID individual) | ❌ Não em v1 — reservado para v2 com consentimento explícito |

### 7.2. Quando disparar cada evento

| Evento | Quando |
|---|---|
| `batch_viewed` | `BatchStatusView` monta e `phase !== 'error_page'` |
| `batch_completed_seen` | `BatchResultBanner` monta (primeira renderização com `phase === 'terminal'`) |
| `batch_error_tab_opened` | Usuário clica no tab "Falhou" (`activeTab` muda para `'failed'`) |

## 8. Comportamento Offline

O polling de status é feito via TanStack Query com retry automático. Comportamento adicional:

1. `window.addEventListener('offline')` → exibir toast `polling_network` imediatamente (sem esperar o próximo tick falhar).
2. `window.addEventListener('online')` → esconder toast e forçar refetch imediato via `queryClient.invalidateQueries(['batch-status', batchId])`.
3. Implementar em `BatchStatusView` com `useEffect` de cleanup.

```typescript
// Em BatchStatusView.tsx
useEffect(() => {
  const handleOffline = () => setIsOffline(true);
  const handleOnline = () => {
    setIsOffline(false);
    queryClient.invalidateQueries({ queryKey: ['batch-status', batchId] });
  };

  window.addEventListener('offline', handleOffline);
  window.addEventListener('online', handleOnline);
  return () => {
    window.removeEventListener('offline', handleOffline);
    window.removeEventListener('online', handleOnline);
  };
}, [batchId, queryClient]);
```
